# 워크플로: 내 상점 만들기

README 2단계에서 AI 에이전트가 따르는 순서입니다. 사용자가 결과를 빨리 볼 수 있도록 질문은 짧게, 작업은 한 번에 끝냅니다.

## 1. 사용자에게 세 가지만 묻기

사용자가 이미 말했다면 묻지 않고 넘어갑니다. 한 메시지에 세 가지를 같이 묻습니다.

1. **무엇을 파는 상점인가요?** (예: 레트로 게임샵, 비건 베이커리, 캠핑 장비)
2. **어떤 분위기인가요?** (예: 8비트 픽셀, 따뜻한 손글씨, 미니멀)
3. **상품은 몇 개로 할까요?** (기본 6개, 최대 12개)

답이 모호하면 그럴듯하게 정하고, 정한 내용을 한 줄로 알려 줍니다. 다시 묻지 않습니다.

## 2. 상점 정보 쓰기 — `seed/shop.json`

- 지금 파일의 필드를 그대로 두고 값만 바꿉니다.
- 상점 이름은 사용자에게 묻지 않습니다. 사용자가 말하지 않았다면 컨셉에 맞게 짓고, 지은 이름을 마무리 안내에서 알려 줍니다. 실존하는 이름을 피하는 규칙은 상점 이름에도 같습니다.
- 테마 색은 대비가 충분한 조합으로 고릅니다. 배경과 글자색의 명도 차이를 크게 둡니다. 화면을 직접 띄워 보지 않는 대신 `npm run check`가 글자와 배경의 대비를 계산해 너무 낮으면 알려 주고, 통과할 때도 계산한 값을 한 줄로 보여 줍니다.

## 3. 상품 쓰기 — `seed/products.json`

- [가드레일의 데이터 규칙](../guardrails.md#데이터-규칙)을 지킵니다.
- 가격은 상점 컨셉에 맞게 서로 다르게 정합니다. 데모에서 "제일 저렴한 상품은?"을 물어보기 때문입니다.
- `featured: true`는 2–3개에만 붙입니다.

## 4. 화면 바꾸기 — `public/`

- `style.css`는 맨 위의 토큰부터 바꿉니다. 토큰은 제자리에서 값만 바꾸고, 그 밖의 규칙은 고치든 파일 끝에 더하든 편한 쪽으로 합니다.
  - 색 네 가지(`--color-primary`, `--color-accent`, `--color-background`, `--color-text`)와 글꼴은 `seed/shop.json`의 `theme`에서 정합니다. 화면에서 그 값이 덮어쓰기 때문입니다. `style.css` 맨 위의 기본값(색 네 가지와 `--font`)도 같은 값으로 맞춰 두면 페이지가 열리는 순간에 이전 디자인이 잠깐 보이지 않습니다. `[data-font="..."]` 묶음은 그대로 둡니다.
  - `--color-card`(카드 배경)와 `--color-on-primary`(primary 색 위의 글자)는 `style.css`에만 있습니다. 배경이나 primary 색의 밝기를 바꿨다면 글자가 보이도록 이 둘도 같이 바꿉니다.
  - `--color-muted`(흐린 글자)와 `--color-line`(테두리)은 글자색에서 자동으로 만들어지니 그대로 둡니다.
- 글자색은 `npm run check`가 대비를 계산하는 조합 안에서만 고릅니다. 배경 위에는 `var(--color-text)`, 카드 위에는 `var(--color-text)`나 `var(--color-primary)`, primary 색 위에는 `var(--color-on-primary)`, 흐린 글자는 `var(--color-muted)`입니다. 새로 넣는 요소에는 글자색을 따로 지정하지 않아도 됩니다. 둘러싼 요소의 글자색을 물려받으면 이 조합이 그대로 유지됩니다.
  - 글자를 `opacity`나 `color-mix`로 흐리게 만들지 않습니다. 검사한 대비보다 낮아집니다. 글자가 보였다 사라지는 깜빡임은 흐리게 만드는 것이 아니니 괜찮습니다. 보이는 동안의 색이 위 조합이면 됩니다.
  - 글자가 아닌 장식(테두리, 글자에 붙는 밑줄, 그림자, 배경 무늬, 따로 놓인 기호)의 색과 진하기는 자유입니다. 글자가 그 위에 놓이는 무늬만 옅게 둡니다(어떤 색이든 바탕색에 15% 이하로 섞은 정도). 글자와 겹치지 않는 장식에는 이 기준이 없습니다. 그 정도면 흐린 글자를 포함해 어떤 글자도 그대로 읽힙니다.
- `index.html`, `product.html`의 문구를 상점에 맞게 바꿉니다. `data-shop` 속성이 있는 요소와 `<title>`은 `app.js`가 `shop.json`의 값으로 덮어쓰는 자리이니, 적혀 있는 기본 문구도 내 상점 이름으로 바꿔 둡니다.
- `app.js`에는 화면에 나오는 문구가 조금 있습니다(재고와 품절 표시, 가격 단위, 상담 버튼을 누르면 채팅창에 미리 들어가는 문장). 필요할 때만 바꾸고, `/api/shop`, `/api/products` 호출은 그대로 둡니다.
- [가드레일의 화면 규칙](../guardrails.md#화면-규칙)을 지킵니다.
- 바꾸는 범위는 문구, 디자인 토큰, 장식까지입니다. 시간 안에 끝내는 것이 우선입니다.
  - 이미 있는 문구를 바꾸는 것, CSS 규칙을 더하는 것, 장식용 요소나 문구를 조금 더하는 것은 괜찮습니다.
  - 페이지 구조(머리글, 상점 소개, 상품 목록, 상품 상세의 배치)를 새로 짜는 일은 사용자가 원할 때만 합니다.
  - 요소를 새로 넣을 때는 `id`나 `data-shop` 속성이 있는 요소(`app.js`가 내용을 채우거나 숨기는 자리) 안이 아니라 그 옆이나 바깥에 넣습니다. 그러면 `app.js`를 고칠 필요가 없습니다.
  - 특정 상품에 대한 사실(성분, 가격, 재고)은 화면 문구가 아니라 `seed/products.json`에 적습니다. 화면 문구와 `seed/shop.json`의 소개는 인사, 분위기, 상점의 원칙처럼 상점 전체에 해당하는 말로 씁니다. 모든 상품에 똑같이 해당하는 사실이라면 성분에 대한 것이어도 상점의 원칙으로 여기에 써도 됩니다. 그런 원칙은 `seed/shop.json`의 `concept`에 꼭 적습니다. AI 상담원은 화면 문구를 읽지 않고 `concept`과 상품 설명만 읽기 때문에, 화면에만 적으면 상담원의 답이 화면과 어긋납니다.

## 5. 검사하기

```bash
npm run check
```

- 결과를 사용자에게 그대로 보여 줍니다.
- 실패하면 메시지가 가리키는 곳을 고치고 다시 실행합니다. 통과할 때까지 반복합니다.

## 6. 마무리 안내

통과하면 아래처럼 짧게 알려 주고 끝냅니다.

> 상점 준비가 끝났어요. 터미널에서 `npm run deploy`를 실행하면 내 D1에 상품이 다시 만들어지고 새 디자인으로 배포됩니다.

배포 명령은 직접 실행하지 않습니다.

## 다시 하고 싶을 때

사용자가 처음부터 다시 하고 싶어 하면, 직접 되돌리지 말고 아래 명령을 안내합니다.

```bash
git restore public seed
```
