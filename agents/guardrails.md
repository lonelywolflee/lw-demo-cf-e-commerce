# 가드레일

AI 에이전트가 고쳐도 되는 범위와 하면 안 되는 일입니다. 이 규칙은 `npm run check`가 검사합니다. 규칙을 어기면 check가 실패하고, 사용자는 배포할 수 없습니다.

여기에 적히지 않은 세부(문구의 말투, 장식의 종류, 파일을 고치는 수단과 방식, 상품의 구체적인 내용)에는 정해진 답이 없습니다. 아래 규칙을 지키는 한 어느 쪽을 골라도 괜찮으니 스스로 정하고 넘어갑니다.

## 고쳐도 되는 파일

| 경로 | 무엇을 바꾸나 |
| --- | --- |
| `seed/shop.json` | 상점 이름, 한 줄 소개, 컨셉, 테마 색·글꼴 |
| `seed/products.json` | 상품 목록 |
| `public/index.html` | 랜딩 페이지 문구와 레이아웃. 요소를 더하거나 빼도 됩니다 |
| `public/product.html` | 상품 상세 페이지 문구와 레이아웃. 요소를 더하거나 빼도 됩니다 |
| `public/assets/style.css` | 디자인 |
| `public/assets/app.js` | 화면에 나오는 문구와 상품을 그리는 모양. API 호출 경로는 그대로 |

위 여섯 파일만 고칩니다. **새 파일도 만들지 않습니다.** 디자인을 나눠 담고 싶어도 `style.css` 한 파일에 씁니다.

여섯 파일 안에서는 [화면 규칙](#화면-규칙)만 지키면 문구·요소·스타일을 자유롭게 바꿔도 됩니다. 다만 시간이 짧으니 [워크플로](workflows/customize-shop.md)가 권하는 대로 디자인 토큰과 문구부터 바꾸고, 레이아웃을 크게 다시 짜는 일은 사용자가 원할 때만 합니다. `app.js`가 값을 채워 넣는 요소(`id`나 `data-shop` 속성이 있는 요소)는 지우면 화면이 비니, 지울 때는 `app.js`도 같이 고칩니다.

## 고치면 안 되는 파일

위 여섯 파일을 뺀 레포의 모든 파일입니다. 대표적인 것과 이유는 아래와 같습니다.
| 경로 | 이유 |
| --- | --- |
| `src/` | 서버 코드. 사용자가 3·4단계에서 주석만 풉니다 |
| `wrangler.jsonc` | 배포 설정과 바인딩. 사용자가 3·4단계에서 주석만 풉니다 |
| `migrations/` | DB 스키마는 고정입니다 |
| `scripts/` | check와 seed 스크립트 |
| `public/assets/chat-widget.js` | 상담 채팅 위젯 |
| `docs/` | 모든 상점에 똑같이 적용되는 공통 정책 문서입니다 |
| `ops/` | 정책 문서와 AI Search 준비 스크립트 |
| `agents/`, `AGENTS.md`, `CLAUDE.md` | 이 규칙 자체 |
| `package.json`, `package-lock.json` | 의존성과 명령어 |
| `README.md`, `ARCHITECTURE.md`, `.gitignore` | 사용자 안내 문서와 설정 |

`git status`에 `wrangler.jsonc`가 이미 수정된 것으로 나올 수 있습니다. 사용자가 1단계에서 처음 배포할 때 `"database_id"` 한 줄이 자동으로 추가되기 때문입니다. 정상이니 되돌리지 말고 그대로 둡니다. `npm run check`도 이 줄은 문제 삼지 않습니다.

## 데이터 규칙

`seed/products.json`은 아래 형식을 지켜야 합니다.

| 필드 | 형식 | 규칙 |
| --- | --- | --- |
| `id` | 문자열 | 영문 소문자·숫자·하이픈, 상품끼리 겹치지 않음 |
| `name` | 문자열 | 1–40자 |
| `category` | 문자열 | 1–20자 |
| `price` | 정수 | 원 단위, 0 이상 10,000,000 이하 |
| `description` | 문자열 | 1–200자 |
| `emoji` | 문자열 | 화면에 한 글자로 보이는 이모지 1개 (상품 이미지 대신 씁니다) |
| `options` | 객체 (선택) | 키는 옵션 이름, 값은 고를 수 있는 것들의 문자열 배열. 예: `{ "사이즈": ["S", "M", "L"] }` |
| `stock` | 정수 | 지금 남은 수량, 0 이상. 0이면 품절 |
| `featured` | 불리언 | 랜딩 페이지에 먼저 보일 상품이면 `true` |

- `emoji`는 화면에 한 글자로 보이면 1개입니다. 내부적으로 여러 코드가 합쳐진 이모지(❤️, 🏷️)도 됩니다. 이모지를 두 개 이상 붙여 쓰거나, 글자·숫자·기호나 국기를 쓰면 `npm run check`가 실패합니다.
- `description`과 `seed/shop.json`의 소개·컨셉은 자유롭게 지어 씁니다. 가상의 상점이니 상품과 상점의 특징은 그럴듯하게 지으면 됩니다. 쓰지 않는 것은 두 가지뿐입니다. 효능이나 안전을 보장하는 말, 그리고 밖에서 인정받았다는 말(인증, 수상, 순위)입니다. 상품의 종류나 만드는 방식을 가리키는 말은 인정받았다는 말이 아니니 써도 됩니다. 무엇이 들어 있고 무엇이 들어 있지 않은지는 사실을 알리는 말이라 괜찮습니다. 안전에 대해서는 성분을 적는 데서 멈춥니다. 그래서 안전하다는 말도, 위험할 수 있다는 말도 덧붙이지 않습니다. 성분이 중요한 상품(먹는 것, 몸에 닿는 것)은 주요 성분의 이름을 설명에 적어 둡니다. 상품을 이루는 주된 것만 적으면 되고, 성분의 성분까지 적을 필요는 없습니다. 옵션에 따라 성분이 달라지면 그것도 적습니다. AI 상담원이 이 설명을 근거로 답하고, 알레르기나 건강에 대한 질문에는 적힌 성분만 알려 주기 때문입니다.
- `stock`이 0인 상품은 화면에 품절로 표시되고 AI 상담원도 재고가 없다고 답합니다. 사용자가 품절 상품을 원한다고 하지 않았다면 모든 상품의 재고를 1 이상으로 둡니다. `stock`은 기간과 상관없이 지금 남은 수량이니, 재고를 보여 주는 화면 문구에 기간을 붙이지 않습니다. 재고와 상관없는 문구에는 해당하지 않습니다.
- `options`의 키는 상품 페이지에 옵션 이름으로 그대로 나오므로 사용자가 읽을 말로 씁니다. 옵션은 여러 개를 둘 수 있습니다. 상품마다 가격과 재고는 하나뿐이라, 무엇을 골라도 가격이 같은 것만 옵션으로 둡니다. 가격이 같다면 상품 자체에 대한 선택이든 덧붙는 선택이든 옵션으로 둘 수 있습니다. 고르는 값에 따라 가격이 달라지는 것은 상품을 따로 만듭니다.
- 상품은 1개 이상 **12개 이하**입니다. AI 상담원이 상품 목록 전체를 읽기 때문입니다.
- 실존하는 이름은 쓰지 않습니다. 실제 회사, 제품, 작품, 인물, 캐릭터의 이름 대신 일반 명사로 짓습니다. 상점 이름도 같습니다. 분야나 기술을 가리키는 일반 용어와 누구나 쓰는 표현은 써도 됩니다. 특정 대상이 떠오를지 애매하면 더 일반적인 이름으로 짓고 넘어갑니다. 지은 이름이 실제로 어딘가에 있는지까지 확인할 필요는 없습니다. 이 규칙은 `npm run check`가 검사하지 않으니 직접 지킵니다.

`seed/shop.json`의 형식은 지금 파일에 들어 있는 필드를 그대로 유지합니다. 필드를 추가하거나 지우지 않습니다.

| 필드 | 형식 | 규칙 |
| --- | --- | --- |
| `name` | 문자열 | 상점 이름, 1–30자 |
| `tagline` | 문자열 | 한 줄 소개, 1–60자 |
| `concept` | 문자열 | 상점 컨셉, 1–100자. AI 상담원의 프롬프트에도 들어갑니다 |
| `theme.primary`, `theme.accent`, `theme.background`, `theme.text` | 문자열 | `#RRGGBB` 형식의 색 |
| `theme.font` | 문자열 | `sans`, `serif`, `mono`, `rounded` 중 하나 |

- `theme.text`와 `theme.background`는 대비가 4.5 이상이어야 합니다. 글자가 배경 위에서 읽혀야 하기 때문입니다.
- `theme.accent`와 `theme.background`도 대비가 4.5 이상이어야 합니다. "오렌지마켓 입점 상점" 배지가 accent 색 바탕에 background 색의 작은 글자로 그려지기 때문입니다.
- 외부 폰트는 쓸 수 없습니다. `theme.font`의 각 이름이 가리키는 글꼴 묶음은 `public/assets/style.css`의 `[data-font="..."]`에 있습니다.
- 네 묶음에 없는 글꼴이 어울리는 분위기라면 가장 가까운 묶음을 고르고, 나머지는 CSS 장식으로 표현합니다. 사용자에게는 글꼴 대신 장식으로 표현했다고 한 줄로 알립니다.

## 화면 규칙

- `index.html`과 `product.html`에서 아래 두 줄은 지우거나 바꾸지 않습니다. 상담 채팅 버튼이 여기에 붙습니다.
  - `<div id="chat-root"></div>`
  - `<script src="/assets/chat-widget.js" defer></script>`
- 상품 데이터는 HTML에 직접 쓰지 않고 지금처럼 `/api/products`에서 받아 그립니다. 그래야 D1에 넣은 상품이 화면에 나옵니다.
- 이 상점은 오렌지마켓에 입점한 상점이고, 배송·환불·멤버십은 오렌지마켓 공통 규정을 따릅니다. 화면의 "오렌지마켓 입점 상점" 배지와 바닥글의 "배송·환불·멤버십은 오렌지마켓 공통 규정을 따릅니다" 문구는 모양·위치·말투를 상점에 맞게 바꿔도 되지만, 이 두 가지 뜻은 화면에 남겨 둡니다. 그 밖의 장식(머리글의 이모지 등)은 이 뜻에 들어가지 않으니 상점에 맞게 바꿔도 됩니다. 상점만의 배송비·환불·멤버십 규정을 지어서 화면이나 상품 설명에 쓰지 않습니다. AI 상담원이 공통 규정으로 답하기 때문에 화면과 답이 달라집니다.
- 글자는 배경 위에서 읽혀야 합니다. `npm run check`가 `style.css` 맨 위의 `--color-card`(위에 `text` 색 글자가 올라감, 대비 4.5 이상)와 `--color-on-primary`(`primary` 색 위에 올라감, 대비 4.5 이상)를 `seed/shop.json`의 색과 비교합니다. 카드 위에 `primary` 색으로 쓰는 가격은 크고 굵은 글자라 `--color-card`와 대비 2 이상이면 됩니다. 이 두 토큰을 `#RRGGBB`가 아닌 값으로 쓰면 계산할 수 없어 검사를 건너뜁니다.
- 이미지·폰트·스크립트·스타일을 외부 URL(`http://`, `https://`)에서 불러오지 않습니다. 이미지는 이모지와 CSS로 표현합니다. 다른 사이트로 가는 일반 링크(`<a href>`)는 괜찮습니다.

## 하면 안 되는 일

- 주석 블록 A·B를 푸는 일 (`wrangler.jsonc`, `src/chat.ts`)
- `npm install <패키지>`, 빌드 도구·프레임워크 추가
- `npm run deploy`, `npm run setup:docs`, `wrangler deploy`, `wrangler d1 ...`, `wrangler r2 ...`, `wrangler ai-search ...` 같은 배포·리소스 명령 실행
- `npm run preview`, `wrangler dev`로 미리 보기 서버 띄우기. 화면은 직접 확인하지 않고 `npm run check` 통과로 마무리합니다. 사용자가 배포한 뒤 브라우저에서 봅니다
- `git commit`, `git push`, `git reset --hard`
- 비밀번호·API 토큰을 파일에 쓰거나 출력하기
